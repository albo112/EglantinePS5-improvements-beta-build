# Eglantine upstream branch audit — 7 November 2026

## Result and coverage

GitHub advertised **175 branches**, rather than 174, at collection time: API pages contained 100, 75, and 0 entries. All 175 distinct API head SHAs exactly matched the complete bare Git clone. Against T34's pinned core `e736dfde9e45bc3640935e373927814883803d95`, 94 heads are ancestors, 15 descendants, and 66 divergent. The new histories contain 561 unique nonbaseline commits; 391 touch the selected GPU, shader, CPU-memory, Dynarmic, or related cache paths. Every head has a per-branch ancestry, commit, changed-file, and disposition entry in the CSV/JSON. Every one of those 391 source patches was compared with the actual T34 source snapshot using forward and reverse applicability checks; those checks are evidence of textual overlap, not runtime correctness. Source files were never executed.

**No advertised head fixes either observed crash boundary.** De-duplicating the precise crashing files across all heads yields two `engine_upload.cpp` blobs and twelve `memory_manager.cpp` blobs. Both upload variants eagerly allocate the full register-declared copy size in `ProcessExec`, even though the native single-line bulk-data path later bypasses that scratch buffer. None of the twelve memory variants validates the whole GPU virtual range in the traversal/query functions before indexing the tables. These conclusions come from extracting and reviewing the affected functions of every unique version, not branch names or commit subjects. See `upstream-crash-path-variants.json` and the separate `upstream-memory-guard-proposal.md`.

T49 comparison uses frontend `25cfc07be0a3675749adece5d012fdb916c4cd48`, core `0ca2032bffc5f1a3fca75427f7d4a4718adda660`. All **257 patch files** present in its patch directory applied successfully to an isolated scratch reconstruction (highest patch number 0265). This reconstruction changes no build checkout and is not a build or console validation.

## Confirmed foliage dependency

The [Lichii PR 395 primary report](https://github.com/zortos293/Lichii/pull/395) documents a successful near-hedge fix and missing Hyrule Field grass after rebuilding formerly null bindings. Independent AMD and NVIDIA reports agree. The [binding-budget investigation](https://github.com/zortos293/Lichii/pull/395#issuecomment-6700675965) shows that filling direct storage slots evicts pointer-table write bindings at the 32-SSBO limit; consumers then see empty instance lists. This explains why enabling null-slot rebuilding alone can exchange one missing-foliage symptom for another.

[PR 423](https://github.com/zortos293/Lichii/pull/423) is now closed without merge and points to PR 434 as the more complete follow-up. PR 423's 64-slot experiment requires widened enable/written masks and device-limit-aware budgeting; increasing a single constant is insufficient. This is outside the 175-head Eglantine inventory and is a follow-up research item, not a recommended untested PS5 merge.

The recommended immediate work is the scoped upload allocation and GPU-range hardening, while retaining a coherent PS5 frontend/driver/core series and the independent depth-float fix. The audit does not claim successful gameplay from source-only evidence.
